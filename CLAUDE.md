# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Одностраничный сайт-портфолио видеопродакшена «ВАРВАЦЫ». Ровно один экран без прокрутки:
папка с веером карточек-превью, кнопка «Открыть папку» под ней и три надписи по углам
страницы — `о варвацы`, `ai creator`, `контакты`.

Статика без сборки и фреймворка: `index.html` + `css/style.css` + `js/main.js` + `js/cards.js`.
Ничего не компилируется, тестов нет. Фреймворк добавлять не нужно — вся страница это один
авторский макет, готовых компонентов под него не существует.

## Запуск

```bash
python -m http.server 5599
```

Открывать `http://localhost:5599`. Конфиг для превью — `.claude/launch.json` (имя `varvacy`).

**Браузер агрессивно кэширует.** У всех ссылок на css/js/картинки стоит `?v=N`. При любой
правке этих файлов номер надо поднять, иначе изменения не увидеть. В `index.html` версия
проставлена в трёх местах: `style.css`, оба `<script>` и `src` картинок.

## Источник истины по геометрии

**`новый макет.svg`** — действующий экспорт из Figma, холст 4691×2536. Все координаты,
размеры, углы поворота и порядок слоёв взяты оттуда, а не подобраны на глаз. Если правится
раскладка — пересчитывать из этого файла, не двигать числа вручную.

`Макет сайта 1.svg` — предыдущая версия (холст 4691×3213, композиция крупнее в 1/0.8876 раза,
внизу были иконки соцсетей). Держать для истории, но за истину не брать.

Ранее координаты выводились подбором по растровым макетам, и два угла оказались неверны
(`contest` −14.75° вместо −27.26°). Растровые макеты (`Как должно быть.png`,
`Положение карточек.png`, `Макет сайта 2.png`) годятся только для сверки внешнего вида.

Экспорт приходит без имён слоёв и с текстом в кривых. Разбирать его приходится по геометрии:
считать габариты путей (в них есть команды `H`/`V` с одной координатой — наивное разбиение
чисел на пары даёт неверный bbox), а надписи опознавать, отрисовав SVG в браузере.

### Система координат

`.scene` — габарит папки с карточками из макета: x 1297..3394.3, y 529..1811.6, то есть
**2097.3×1282.6** единиц макета (`aspect-ratio: 2097.3 / 1282.6`). Всё внутри позиционируется
в процентах от неё, поэтому композиция масштабируется целиком одним числом.

Надписи по углам к сцене не привязаны — они прижаты к краям окна (`.mark`, `vw`/`svh`).
Кнопка `.cta` лежит в системе сцены, ниже её габарита (`top: 110.67%`).

Единственная величина, задающая размер, — `--scene-h` в `.stage`. `container-type: size` на
`.scene` даёт единицы `cqw`/`cqh` (1% ширины/высоты сцены) — ими заданы радиус размытия и
скругления, чтобы они масштабировались вместе с композицией.

### Три вещи, которые легко сломать

1. **`perspective` должна стоять на `.scene`, а не на `.stage`.** Свойство действует только на
   прямых детей. Папка — ребёнок сцены; при перспективе на `.stage` её поворот схлопывается в
   плоскость и наклон выглядит как лёгкое сжатие без объёма.

2. **Карточки в PNG крупнее, чем в макете.** Вокруг тела карточки в файле ~44 px прозрачной
   тени, а прямоугольники в SVG описывают именно тело. Поэтому позиция карточки считается со
   смещением на габарит непрозрачной области внутри её PNG (`--ox`/`--oy` — там же точка
   поворота). Не сопоставлять размер PNG с размером прямоугольника из макета напрямую.

3. **Области наведения `.hit` не должны быть детьми `.card`.** Они лежат отдельным
   неподвижным слоем (`.hits`, z-index 9) и построены по прямоугольникам карточек из макета.
   Если положить их внутрь карточки, при подъёме область уезжает из-под курсора: срабатывает
   уход, карточка падает, область возвращается — и она начинает дрожать вместо удержания.

### Слои внутри `.folder` (z-index)

`back` → карточки `1..6` → `.hits` `9` → `.blur` `10` → `.glass` `11`.

Порядок карточек снизу вверх — как в SVG: `contest, atmo, music, cartoon, anim, logo`.
Он постоянный: при наведении карточка поднимается, **не меняя слой**.

### Передняя часть папки

`.front` — непрозрачная картинка с фактурой (`новое в папке.png`). Надписей в ней нет,
`ПОРТФОЛИО / ВАРВАЦЫ` лежат отдельно в `.front-text` — вектором из макета.

Высота `.front` задана явно, а не `auto`: непрозрачная область PNG сажается на контур папки
из макета, а пропорции у них расходятся на 0.6%. Разница незаметна, зато контур совпадает.

**Раньше здесь было стекло с `backdrop-filter`, и его пришлось убрать по производительности.**
Замер на машине заказчика: худший кадр 33 мс со стеклом против 16 мс без него, 35 fps против
60. Размытие обязано пересчитываться каждый кадр, потому что за стеклом всё время движутся
карточки и наклоняется папка. При 60 Гц на кадр есть 16 мс, и одно размытие съедало 17.
Возвращать `backdrop-filter` без замера не стоит.

### Раскладка в один экран

`.scene` сдвинута вверх через `margin-bottom: calc(0.1728 * var(--scene-h))`: кнопка висит
под сценой, и без сдвига по центру экрана оказалась бы папка, а не группа целиком. В макете
папка тоже чуть выше середины холста именно из-за кнопки.

Размер задаёт `--scene-h: min(calc(44.7vw / 1.63522), 62svh)` — 44.7% ширины это доля папки
от ширины холста в макете. На экранах уже 900px эта доля даёт слишком маленькую папку,
поэтому там отдельное правило с `92vw`.

## Анимации

`js/main.js` — наклон папки за курсором. Целевой угол догоняется интерполяцией в
`requestAnimationFrame`, цикл засыпает в покое. `transform` пишется напрямую в `style`:
через CSS-переменные браузер пересчитывал стили всего поддерева на каждом кадре. Геометрия
папки закэширована, `getBoundingClientRect` на каждое движение мыши вызывать нельзя.

`js/cards.js` — подъём карточек. Ведётся покадрово скриптом, а не переходом CSS, ради одного
требования: **подъём нельзя прерывать**. Если курсор ушёл раньше, чем карточка дошла до
верха, спуск ставится в очередь и стартует по завершении подъёма. Фазы: `idle → rise → hold →
fall`. Скрипт ставит на `<body>` класс `js-cards`, который гасит переход в CSS.

Настройки в начале файла: `LIFT` (доля высоты сцены), `RISE`, `FALL`.

Кривая затухания — квадратичная. Экспоненциальная и кубическая дают длинный хвост: у
экспоненты половина времени уходит на последние 3% пути, и карточка визуально зависает
у верхней точки.

### Тач-экран

Обе анимации работают и без мыши — гейтов по `(hover: hover)` в скриптах больше нет.

**Карточки поднимаются по нажатию пальца**, а не по наведению: `pointerdown` — вверх,
`pointerup` — вниз. Отдельная механика «подскока» не понадобилась: тап отпускают за
~150 мс, а подъём не прерывается, поэтому карточка сама доходит до верха и идёт обратно.
У тач-указателя нажатие неявно захватывает элемент, так что `pointerup` придёт на ту же
`.hit`, даже если палец с неё сполз.

Мышь и палец обязательно разводить по `e.pointerType`. Общий обработчик `pointerup`
ронял бы карточку прямо под курсором: у мыши отпускание кнопки не значит ухода.

**Папка кренится за пальцем.** `pointermove` на тач-экране приходит только пока палец на
стекле, поэтому наклон живёт во время проведения и сбрасывается по `pointerup`. Наведение
висит ещё и на `pointerdown`: на мыши папка кренится уже от наведения на карточку, и без
этого на телефоне наклон увидел бы только тот, кто повёл пальцем.

Гироскоп (`deviceorientation`) сознательно не берём. Он требует HTTPS, а в Safari ещё и
`requestPermission()` строго из жеста пользователя: системный диалог, и отказ необратим —
переспросить можно только после сброса данных сайта в настройках телефона.

### Как проверять анимации

Панель предпросмотра в этой среде **не отрисовывает кадры** — `requestAnimationFrame` в ней
замирает, и переходы CSS остаются на первом кадре. Скриншотом плавность не проверить.

Рабочий способ — прогнать сам файл в Node с заглушкой DOM и виртуальными часами: подменить
`document`, `performance.now`, `requestAnimationFrame`, `matchMedia`, `getComputedStyle`,
затем `eval` файла и ручная прокрутка времени. Так проверяются реальные величины: доходит ли
подъём до 100%, сколько времени карточка проводит у верхней точки, возвращается ли в ноль.
Этим способом уже находились настоящие ошибки (подъём обрывался на 89.5%).

Для статических проверок годится браузер: положения элементов, `getComputedStyle`,
`elementFromPoint` для хит-теста областей наведения.

Плавность на живой машине меряет `js/dev.js`: открыть страницу с `?fps`, в углу появится
счётчик и **худший кадр за полсекунды**. Средний fps подвисания маскирует, худший кадр —
нет. В обычном режиме скрипт ничего не делает.

Проверять раскладку надо **по видимым размерам**, а не по атрибутам. На фильтрах это уже
подводило: скрипт ставил плиткам `hidden`, проверка по атрибуту проходила, а на экране
ничего не менялось — `display:grid` у `.tile` перебивал скрытие. Меряйте
`getBoundingClientRect()`.

## Открытая папка

Кнопка «Открыть папку» показывает `.fv` — белую панель на 88% экрана: столбик фильтров
слева, сетка превью справа, иконки соцсетей внизу. Логика в `js/folder.js`, закрытие по
крестику, Esc и клику мимо панели. Пока панель открыта, `body` получает класс `fv-open`,
и наклон папки под ней не считает кадры впустую.

**Появление держится на одной прозрачности, и менять это не стоит.** Здесь дважды ловились
рывки, оба раза по одной причине — браузер заново растеризовал крупную панель с картинками:

1. `transform: scale` на панели — растеризация на каждом кадре масштабирования. Убрано.
2. `display: none` в закрытом состоянии — при каждом открытии заново считалась раскладка
   и первый кадр рисовался с нуля. Панель теперь всегда просчитана, а прячется через
   `visibility: hidden` (он же снимает её с кликов и обхода по Tab) плюс `opacity`.

Ещё раньше момент скрытия ловился по `transitionend`, но это событие всплывает от любого
потомка — от картинки плитки, от кнопки фильтра — и панель пряталась посреди собственной
анимации. Сейчас состояние — один класс `is-open`, без таймеров и событий.

Пропорции сетки сняты с `Макет открытой папки.png`: плитка 13.1% ширины экрана, промежуток
7.0%, боковой столбик 13.75%. Сетка намеренно воздушная — промежутки шире, чем кажется
разумным на глаз.

**Категории фильтров расставлены наугад** и ждут подтверждения: атрибут `data-cat` у каждой
плитки в `index.html`. У «Работа с 3D блендером» роликов нет, поэтому там пустое состояние.

Превью — кадры из видео (`assets/posters/*.webp`, 720x405, кроп по центру). Пересобираются
через `ffmpeg` с указанием секунды для каждого ролика.

Подписи под превью — живой текст фирменным шрифтом Abibas (`assets/fonts/abibas.woff2`,
23 КБ, собран из `шрифт/Abibas.ttf` через fontTools). Кегль подобран так, чтобы самое
длинное название — «Мультик-судьба» — влезало в ширину плитки без переноса.

До появления файла шрифта подписи вставлялись кривыми из макета, с разворотом из наклона
карточек и поправкой кегля у каждой. Всё это больше не нужно: если добавится ролик,
достаточно дописать плитку с обычным текстом.

## Надписи

`о варвацы`, `ai creator`, `контакты`, `Открыть папку` — фирменный шрифт, вставлены прямо
в `index.html` инлайновым SVG: масштабируются без потери качества, не ждут загрузки шрифта
и не создают лишних запросов.

`ai creator`, `контакты` и `Открыть папку` взяты кривыми из макета. `о варвацы` в макете нет —
её путь собран из `assets/fonts/abibas.woff2` через fontTools (это тот же фирменный шрифт:
контур «контакты» из ttf совпал с контуром из макета). Масштаб пути — 0.08549 от единиц
шрифта, тот же, что у остальных надписей; ось Y перевёрнута, начало координат сдвинуто в
левый верхний угол габарита.

Все надписи выводятся в коробке одной ширины (`--mw` в `.mark`), поэтому у более длинной
`о варвацы` ширина домножена на отношение viewBox — иначе её буквы вышли бы мельче соседних.

`о варвацы` и `контакты` — кнопки, открывающие всплывающие окна (`js/contacts.js`, один
обработчик на все `.mark__btn[aria-controls]`). Окно `о варвацы` висит у верхнего края,
поэтому раскрывается вниз (`.pop--about`). Пасхалка с сердечками (`js/hearts.js`) висит на
`ai creator` — кнопка помечена классом `mark--egg`.

Текст в окне набран тем же приёмом, что описание ролика: связный текст — нейтральным
шрифтом, ключевые слова — Abibas. Две тонкости, на которых это ломается: приглушать абзац
надо цветом с альфой, а не `opacity` (свойство гасит и выделенные слова), и выделениям
нужен свой `line-height` — иначе строки с ними разъезжаются шире соседних, потому что
высоту строки задаёт самый рослый инлайн-бокс.

## Оптимизация

Картинки папки и карточек отдаются в двух размерах через `srcset`: полный (0.9 от макета)
и половинный (0.45). Телефон получает облегчённые — первая загрузка 538 КБ вместо 1405 КБ.
`sizes` у каждой карточки свой, посчитан от её доли ширины сцены.

Предзагрузка передней части папки идёт через `imagesrcset`/`imagesizes`, а не простым `href`:
иначе браузер тянул бы полную версию вдобавок к той, что реально выберет `srcset`.

Превью в панели помечены `fetchpriority="low"` — они нужны только после открытия папки и не
должны соперничать с главным экраном. `loading="lazy"` им не подходит: первое открытие
панели тогда ждёт загрузку.

Видео грузится только открытое, при закрытии плеера источник снимается — иначе браузер
продолжает докачивать ролик в фоне.

## Ассеты

`assets/*.webp` собираются из PNG в корне проекта (файлы с русскими именами — исходники,
не удалять). Масштаб **0.9** от размера макета: это 2x для типового экрана, при этом
1.17 МБ против 6.4 МБ у исходных PNG.

Пересборка — Python с Pillow, `Image.LANCZOS`, WebP quality 90. В системе доступен `ffmpeg`.
`assets/icons/*` используются в окне контактов. Брать их из `ТГ.png` / `Макс.png` /
`Инстаграм.png`, а не из SVG: там они вставлены с кадрированием через `patternTransform`
и вытаскиваются обрезанными неверно.

## Выкладка

На хостинг заливается **только папка `site/`** — 48 файлов, 57.5 МБ. Остальное в корне
проекта это исходники (макеты, SVG, оригиналы видео, шрифт), они нужны для работы, но в
открытом доступе им делать нечего.

Пересобрать `site/`: скопировать `index.html`, `css/`, `js/`, `assets/` и `robots.txt`.
Проверялось побайтовой сверкой с рабочей версией и сравнением раскладки — совпадает до
пикселя.

Ссылки внутри относительные, поэтому сайт работает и в корне домена, и в подпапке.

Живёт на Vercel: **https://portfoliovarvacy.vercel.app**. `og:url` и `og:image` в
`index.html` прописаны полным адресом — с относительным Телеграм отдаёт карточку ссылки
без картинки. При переезде на свой домен заменить оба.

`.vercelignore` держит `CLAUDE.md` вне деплоя: без него он лежал бы в открытом доступе
по `/CLAUDE.md`.

Заливать надо **содержимое** этой папки, чтобы `index.html` оказался в корне деплоя.
Перетаскивание в браузер один раз уже потеряло целиком папку `js/` — картинки и стили
отдавались, а все семь скриптов ловили 404, и страница стояла мёртвой. Надёжнее CLI:
`npx -y vercel@latest --prod` из этой папки. После выкладки проверять не глазами, а
запросами: `/js/main.js` и `/css/style.css` должны отдавать 200.

Хостинг должен отдавать видео по частям (Range-запросы) — иначе перемотка в плеере будет
перезагружать файл целиком. Обычные статические хостинги это умеют.
